# Smartiz — AI-Powered Educational Platform

## Project Overview

Smartiz is an AI-powered educational platform being rewritten from scratch. Old project lives at `smartiz-application` (Cloudflare D1/SQLite + Hono). This is the new version using PostgreSQL + portable architecture.

The platform includes: AI-powered chat for students, educational content management (education levels → textbooks → chapters → lessons), school/class management, virtual coin system, teacher-student connections, and admin panel.

## Key Architectural Patterns

### Adapter/Interface Pattern
Every external service goes through an interface. Switching providers = changing config, not code.

- **Database** (`@smartiz/db`): `createDb(connectionString)` factory. Works with any PostgreSQL (self-hosted, Supabase, etc.). For Workers, uses Hyperdrive: `env.HYPERDRIVE.connectionString`.
- **Storage** (`@smartiz/storage`): `StorageProvider` interface. Adapters: `LocalStorageAdapter` (dev), `R2StorageAdapter` (via S3 API), `S3StorageAdapter`. Switch via `STORAGE_PROVIDER` env var.
- **Auth** (`@smartiz/auth`): `OTPProvider` interface with `send(phone, code)` method. `MockOTPProvider` for dev. JWT via `jose` library. Middleware: `protect`, `protectAdmin`, `protectSuperAdmin`.

### API Dual Deployment
- `src/index.ts` — `createApp(env)` returns a Hono app (no server)
- `src/entry-node.ts` — Node.js entry (dotenv + @hono/node-server)
- `src/entry-workers.ts` — Workers entry (singleton pattern, Hyperdrive binding)

### Environment Configuration
All config via env vars. See `.env.example` for full list. Loaded through `packages/shared/src/types/env.ts` (`EnvConfig` interface).

### Local Database (Docker)
A `docker-compose.yml` at project root provides an isolated PostgreSQL container:
- **Container**: `smartiz-postgres` on port `5433`
- **Credentials**: user=`smartiz`, password=`smartiz`, db=`smartiz`
- **Connection string**: `postgresql://smartiz:smartiz@localhost:5433/smartiz`

Docker commands:
- `pnpm docker:up` — Start PostgreSQL container
- `pnpm docker:down` — Stop container (data preserved)
- `pnpm docker:reset` — Delete data and start fresh

### Using Remote Database
To develop against a real remote database (Supabase, Liara, VPS), just change `DATABASE_URL` in `apps/api/.env`:
```bash
# Supabase
DATABASE_URL=postgresql://postgres.[ref]:[password]@aws-0-[region].pooler.supabase.com:6543/postgres

# Liara
DATABASE_URL=postgresql://user:password@host:5432/smartiz

# VPS
DATABASE_URL=postgresql://user:password@your-vps-ip:5432/smartiz
```
No code changes needed. The same Drizzle ORM + migrations work with any PostgreSQL.

### Local Development Workflow
1. Start database: `pnpm docker:up`
2. Apply migrations: `pnpm db:migrate`
3. Start dev: `pnpm dev`

### Database Commands
- `pnpm db:generate` — Generate migration files from schema changes
- `pnpm db:migrate` — Apply pending migrations to the database
- `pnpm db:studio` — Open Drizzle Studio at `https://local.drizzle.studio` to browse tables, view data, and run queries

### Database Schema Change Workflow
When modifying the database schema, ALWAYS follow these steps in order:

1. **Edit schema** — Add/modify tables in `packages/db/src/schema/`
2. **Export** — Make sure new tables are exported from `packages/db/src/schema/index.ts`
3. **Generate migration** — Run `pnpm db:generate` to create migration SQL files
4. **Backup database** — Before applying migration, create a backup:
   ```bash
   pg_dump -U <user> -d smartiz -F c -f backup_$(date +%Y%m%d_%H%M%S).dump
   ```
   Or for plain SQL backup:
   ```bash
   pg_dump -U <user> -d smartiz > backup_$(date +%Y%m%d_%H%M%S).sql
   ```
5. **Review migration** — Check the generated SQL in `packages/db/drizzle/` before applying
6. **Apply migration** — Run `pnpm db:migrate`
7. **Verify** — Run `pnpm db:studio` to verify tables and data are correct

**IMPORTANT**: Never apply migrations without generating them first. Never apply migrations without a backup.

### SQLite to PostgreSQL Conversion Reference
When porting tables from old project:
- `sqliteTable` → `pgTable`
- `integer().primaryKey({ autoIncrement: true })` → `serial().primaryKey()`
- `text` timestamps → `timestamp("col", { withTimezone: true }).defaultNow()`
- `real()` → `doublePrecision()`
- `integer` booleans → `integer` (kept as 0/1 convention)
- `sql\`(datetime('now'))\`` → `.defaultNow()` or `sql\`now()\``

## Coding Conventions

- TypeScript strict mode enabled everywhere
- Use `export` not `export default` for schema, types, and utilities
- File naming: kebab-case for files (`file-uploads.ts`, `education-levels.ts`)
- Import workspace packages with `@smartiz/` prefix (e.g., `import { createDb } from "@smartiz/db"`)
- Add `.js` extension in imports for ESM compatibility (e.g., `"./schema/index.js"`)
- No comments unless the WHY is non-obvious
- No unnecessary abstractions — three similar lines is better than a premature one

## Adding New Tables

1. Create `packages/db/src/schema/<table-name>.ts` using `pgTable` from `drizzle-orm/pg-core`
2. Export from `packages/db/src/schema/index.ts`
3. Follow the **Database Schema Change Workflow** above (generate → backup → migrate)
4. Reference old schema at `smartiz-application/apps/api/src/db/schema.ts` for SQLite→PostgreSQL conversion patterns

## Adding New Storage/OTP Providers

1. Implement the interface (`StorageProvider` or `OTPProvider`)
2. Add adapter file in the corresponding `src/adapters/` or `src/otp/` directory
3. Add to factory function in the package's `src/index.ts`
4. Add provider name and config to `packages/shared/src/types/env.ts`
5. Add env vars to `.env.example`

## Adding New API Routes

1. Create route file in `apps/api/src/routes/<route-name>.ts`
2. Use `new Hono()` for the sub-router, export it
3. Mount in `apps/api/src/index.ts` with `app.route("/api/<path>", routeName)`
4. Use middleware from `@smartiz/auth` for protected routes: `protect`, `protectAdmin`, `protectSuperAdmin`
5. Access DB via `c.get("db")`, storage via `c.get("storage")`, env via `c.get("env")`
